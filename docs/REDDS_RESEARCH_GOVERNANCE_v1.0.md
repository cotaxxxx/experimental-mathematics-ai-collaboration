# REDDS｜研究体制・権限・運用 統合ノート v1.0

**版：v1.0（2026年11月22日）**  
**制定・最終判定：Judge（古田勝士）**  
**基準日：2026年11月22日**  
**位置づけ：研究手法と運用規則の統合ノート（コラム形式ではない）**

この文書は、研究の役割分担、特別リソースの使用権限、監査と判定の順序を整理する。個別研究の証明結果や証拠等級を、このノートだけで変更するものではない。

## 1．REDDSの研究循環

**See → Dig → Doubt → Empty → Rebuild → See → …**

研究では左から See、Dig、Doubt、Empty、Rebuild の順に進む。下の合成式では右端の S が最初に作用する。式を左から読んだ五つの頭文字が REDDS である。

$$
\mathrm{REDDS}=R\circ E\circ D_{\mathrm{doubt}}\circ D_{\mathrm{dig}}\circ S
$$

| 作用 | 研究上の意味 |
|---|---|
| **See（見）** | 現象、数値、失敗、例外を観察する |
| **Dig（掘）** | 問いを掘り、仮説や新しい問いを生成する |
| **Doubt（疑）** | 推論、数式、実装、証拠を検証する |
| **Empty（空）** | 根拠を失った前提・主張を取り除くか格下げする |
| **Rebuild（再）** | 問い・定義・座標・手法・検証を再構成する |

**Guarded Empty：** 疑わしいという理由だけで消さない。撤回・縮小の根拠を確かめ、その確認の正しさまで点検する。

五つの「作用」と、次の六つの「担当役割」は区別する。

## 2．研究体制：六つの役割

| 役割 | 担当 | 主な責任 |
|---|---|---|
| **Dig（通常研究）** | ChatGPT | 問いの探索、資料調査、研究設計、計算・実装、成果物作成 |
| **Doubt（通常監査）** | Claude | 数学的検証、反例探索、証拠照合、監査報告 |
| **特別Dig** | ChatGPT Work（Astra・Codex） | 高度な研究、独立計算核、専門的実装、大規模計算の設計と束の作成（実行は研究 PC） |
| **特別監査** | Claude Code | コード監査、独立再計算、実装等価性・再現性の検証 |
| **外部監査** | Muse | 監査系統から独立した追加検証、証明の再評価 |
| **Judge** | **古田勝士** | 研究方針、証拠採否、開始・中止・再開、最終判定 |

- Claude（通常監査）は、作る側の設計と計算をしない。手元で行うのは、hash の照合や選び方の再現のような短い確認だけとする。

- 特別 Dig（Astra）は単発の替刃とする。研究 PC の運用と見張りはしない。

- 特別監査（Claude Code）は、作る側の設計・実装を代行しない。独立検証の完了前に、監査用に作成した独立実装を作る側へ渡さない。

- 特別監査の「コード監査」（対象実装を読む）と「独立実装による検証」（相手の実装を読まない）は別工程とする。独立性を称する検証では、相手側の実装を読んでいないセッションを使う。読んだことが判明したら独立実装を停止し、Judgeに報告する。

**基本原則：作る側・監査する側・外部監査・最終判定者を分離する。**

## 3．使用権限

### 研究提案権：通常はClaude、例外的に全参加AI

- **通常の提案担当はClaude（Doubt）のみ**とする。研究方針、監査方法、運用規則の改善、特別な研究・監査資源の利用について、通常はClaudeがJudgeへ提案する。
- **その他の研究参加AI（ChatGPT／Dig、Astra、Codex、Claude Code、Muse、今後Judgeが参加を認めるAI）**も、特別に必要な場合に限り提案できる。その際は理由、目的、対象範囲、費用・実行負荷への影響を明示する。
- 提案は事前許可なく提出できるが、**提案権は承認権・実行権・中止裁定の解除権を含まない**。提案を採用するかどうか、実際に着手するかどうかはJudgeが最終決定する。
- 提案の受付と承認を区別し、Judgeの承認がない特別リソース投入・新規計算・再開を行わない。

### 特別Dig

ChatGPT Work（Astra・Codex）を使用するかどうかは、**Judge（古田勝士）が決定**する。原則として**Claudeが使用の必要性を提案**する。その他の参加AIは、特別に必要な場合に限り理由を付して提案できる。いずれの提案も起動・実行の許可ではない。

### 特別監査

Claude Codeを使用するかどうかも、**Judgeが決定**する。原則として**Claudeが特別監査の必要性を提案**する。その他の参加AIは特別に必要な場合に限り理由を付して提案できる。提案は承認ではなく、通常監査から自動的に特別監査へ移行しない。

**Fable 5.2 による査読：** Fable 5.2 はAnthropicのAIモデル（モデルID：`claude-fable-5-2`）であり、六つの役割とは別の新しい担当者ではない。証明の査読には、Judgeの承認を受けたClaude Codeのセッションから利用する。通常はClaudeが必要性を判断してJudgeへ提案する。ほかの参加AIは特別に必要な場合に限り提案できる。使用時には実際のモデル名・セッション、対象範囲、査読結果を監査記録に残す。提供元・対応環境：[Anthropicのモデル資料](https://platform.claude.com/docs/en/models/fable-5-2/overview)、[Claude Codeのモデル設定](https://support.claude.com/en/articles/11940350-claude-code-model-configuration)。

### 外部監査

Museを使用するかどうかは、**JudgeとClaudeが判断**する。Claudeは必要性を評価し、**Judgeが最終承認**する。外部監査は全案件に必須ではない。

### Judgeの最終権限

研究の開始・中止・再開、研究方針の変更、数学的成果と証拠の採否、特別Dig・特別監査の利用許可、Muse利用の最終承認はJudgeに属する。

作業を引き継ぐときは、役割名と実際の担当者・セッションを併記する。指示をどこへ送ったか、相手が受領したか、依頼した作業を完了したかを分けて記録する。

## 4．標準的な研究・監査・判定の手順

1. **観察と定式化（See）**：研究対象、問い、原始定義、パラメータ範囲を明確にする。

2. **研究と生成（Dig）**：解析、計算、実装、草稿、証拠候補を作る。特別DigはJudgeが許可した場合に限る。

3. **検証（Doubt）**：Claudeが反例探索・独立照合・論理監査を行う。特別監査の投入はJudgeが判断する。計画を監査するときは、計算をどこで流すか（研究PCか、Judge承認済みの監査環境か）も確かめる。独立検証の前には、監査側の実装参照履歴とセッションを明示する。

4. **追加の外部監査**：必要性はJudgeとClaudeが検討し、Judge承認時にMuseを使用する。

5. **採否と進退（Judge）**：成果の採否（採用・条件付き採用・保留・差戻し）と、研究を続けるか中止するかを分けて記録し、それぞれに対象範囲と理由を添える。

6. **修正と再構築（Empty／Rebuild）**：監査結果と裁定に応じ、誤った前提を撤回・格下げし、必要な場合は問いから組み直す。

### 証拠の区別

- **探索・診断**：予想、試算、費用較正。数学的証明の完成を意味しない。

- **技術的な照合**：SHA-256ではファイルの内容を照合する。ビット一致は試験した入力で出力が一致したことを示す。二つの包囲区間が交わる試験では、その入力で両者が両立したことまでを記録する。

- **数学的監査**：適用範囲、数式、丸め、被覆、境界、依存条件を検査する。

- **Judge裁定**：認めた主張・対象範囲・条件を固定し、別領域への無断拡張を許さない。

## 5．実行・保存・中止の運用

- **通常の計算**：短い確認を除き、計算は研究PCでDigが流す。AIの作業機では長い計算を回さない（AIの利用には費用と上限があり、研究PCは計算のために導入した）。

- **特別監査の独立再計算**：実行場所（Claude Code環境か研究PCか）、担当、計算時間・費用・条件は、**Judgeが案件ごとに決定する未裁定事項**である。Judgeが明示的に承認するまで新たな監査再計算を開始しない。研究PCを使う場合も、監査用の式・コード・入力固定・実行ログを分け、独立性を実行場所だけで判定しない。

- **短い照合**：通常監査Claudeの手元では、hash照合、標本の選び方の再現などの短い確認に限る。

- 計算は、**計画の事前宣言 → 監査 → 条件固定 → 実行許可**の順に実施する。

- 研究PCでは、指示のない再実行・再開・環境変更・重い計算の重複実行をしない。

- 束のSHA-256、内部マニフェスト、ログ、結果の件数、保存先GitHubのコミットを記録する。

- 独立検証を行うときは、生成側と監査側がそれぞれ使った式・実装、共有した入力、実際の実行環境、担当セッションと参照履歴を明記する。**相手側の実装を読んだセッションの再実装を、相手側実装から独立した実装と呼ばない。** その事実が判明した場合、独立実装の作業を停止しJudgeへ報告する。ただし、対象実装を読む通常のコード監査自体は禁止しない。盲検で照合する場合は、参照値を開く前に検証側の出力を固定し、事前に公開されていた標本と区別する。

- Judge が研究の中止を決めたら、新規投入と自動再開を止め、実行中の計算の停止を確認する。完了した結果と未判定の項目を記録し、証拠・途中記録・公開成果は原則保存する。再開は Judge が裁定する。

**適用例（2026年11月22日）**　三軸楕円体研究では、E3 の92組すべてで二つの包囲区間が交わった。うち72点の参照値は公開済みで、盲検照合の対象は20箱だった。一方、独立の核はタイル (2,5) と (3,7) で、点でも下端が正にならなかった（点での包囲の幅が約 4〜10。記録上の範囲は 4.2〜4.6 および 9.5〜10.4）。**chat の見込みでは**、E4 の 8 組のうち 6 組は完走しないと予測されていた（E4 の実行結果ではない）。研究 PC で流す予定だった参照の計算の指示（`370b07d`）は、中止にあわせて取り下げ、流していない。Judge は三軸の研究を中止し、それまでの証拠と Zenodo の公開成果を保存した。裁定の対象は三軸楕円体研究に限る。[E3 の照合記録](https://github.com/cotaxxxx/bg-triaxial-family/blob/c157cc6/evidence/chat/2026-11-22/E3_INPUT_EQUATOR/CHAT_VERIFY_E3.md)・[中止裁定](https://github.com/cotaxxxx/bg-triaxial-family/commit/686343fdf9349fd15cd5324457bd44aaa6af5dde)

## 6．権限の要約

| 判断・仕事 | 担当 |
|---|---|
| 通常の研究・実装 | ChatGPT（Dig） |
| 通常の監査 | Claude（Doubt） |
| 通常の研究・監査・運用提案 | **Claudeのみ** |
| 特に必要な場合の例外的提案 | **すべての参加AI（理由・目的・範囲を明示）** |
| 特別Digの使用提案 | **原則Claude／例外的に他の参加AI** |
| 特別Digの使用承認 | **Judge** |
| 特別監査の使用提案 | **原則Claude／例外的に他の参加AI** |
| 特別監査の使用承認 | **Judge** |
| Fable 5.2 での査読の使用提案 | **原則Claude／例外的に他の参加AI** |
| Fable 5.2 での査読の使用承認 | **Judge** |
| 特別監査の独立再計算の実行場所 | **Judgeが案件ごとに裁定** |
| Museの使用判断 | **JudgeとClaude／Judge最終承認** |
| 成果の採否 | **Judge** |
| 研究の開始・中止・再開 | **Judge** |

**統治原則：問いを掘る能力と、疑う能力を分離する。通常の提案はClaudeが担当し、特別に必要な場合のみその他の参加AIも提案する。提案と承認・実行を分離し、最終判定はJudgeが行う。**

**未裁定事項（v1.0時点）：** 特別監査の独立再計算を実行する場所・実行者・資源条件。Judgeによる個別裁定を要する。
