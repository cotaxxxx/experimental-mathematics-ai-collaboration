# Experimental Mathematics × AI Collaboration

A documented case study of human–AI collaborative research in experimental mathematics.

This repository records not only successful results, but also hypotheses, computational stops, incorrect diagnoses, corrections, verification, literature audits, and restarts. Its organizing principle is:

> **Observe → Doubt → Stop → Re**

Japanese:

> **見る → 疑う → 止める → 再する**

## Re

**Re** is intentionally used as a methodological term rather than as an abbreviation for a single action. It includes recalculation, re-examination, re-verification, re-search, reconsideration, restart, and reproduction. The purpose is not merely to redo what failed, but to return deliberately to a result, assumption, computation, source, or interpretation and examine it again.

## Process provenance

> **Process provenance:** The underlying computational and certification records remain in the original project repositories. This repository references those records rather than replacing them, preserving the distinction between mathematical evidence and retrospective methodological analysis.

This repository therefore does **not** replace mathematical proof records, certification ledgers, source code, or original computational artifacts. It records and analyzes the research process that connects them.

## Repository structure

- `PROCESS_LOG.md` — chronological, append-only summaries of research-process events.
- `CORRECTIONS.md` — index of incorrect diagnoses, corrections, and the evidence that justified each correction.
- `docs/` — detailed case studies linked from the process log and correction index.

## Recording principle

The record should not rewrite events into a clean story after the fact. Failed hypotheses, stops, reversals, corrections, and unresolved points are retained when they materially affected the research process.

The central object of this repository is therefore not a history of success, but a record of **correctability**.
